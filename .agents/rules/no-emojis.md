# Rule: No Emojis in Documentation or Code

## Scope
This rule applies across the entire repository to all documentation, specifications, design artifacts, tasks, comments, and source code.

## Directives
1. **Zero Emojis**: Do not use any emoji characters in markdown documents, specs, plans, tasks, checklists, or source code.
2. **Professional Formatting**: Use standard text labels, GitHub markdown alerts (such as NOTE, IMPORTANT, WARNING), or conventional badges without emoji iconography.
3. **Task and Checklist Syntax**: Ensure tasks and checklist headers strictly avoid emoji characters (use [MVP] instead of target icons, and [CRITICAL] or [WARNING] instead of warning icons).
